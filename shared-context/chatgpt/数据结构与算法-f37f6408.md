### 用户

为什么顺序表时间复杂度是一 单链表是n

### 助手

关键在于：顺序表可以直接通过下标找到元素，而单链表必须一个一个往后找。

① 顺序表为什么是 O(1)

假设数组：

纯文本
下标：  0   1   2   3   4   5
数据：  A   B   C   D   E   F

如果我要找 data[4]：

纯文本
直接 → data[4] → E

计算机可以通过公式直接算出地址：

\[ 地址 = 首地址 + 下标\times 元素大小 \]

所以不管有多少个元素，访问第几个都只需要一次计算。

因此：

\[ \boxed{O(1)} \]
② 单链表为什么是 O(n)

单链表是这样：

纯文本
头
 ↓
[A] → [B] → [C] → [D] → [E] → [F]

假如我要找第 5 个元素 E。

不能直接：

纯文本
head → E ❌

因为头结点只知道下一个节点：

纯文本
A → B → C → D → E

所以必须：

纯文本
A 找 B
B 找 C
C 找 D
D 找 E

如果有 n 个节点，最坏情况下可能要找 n 次。

因此：

\[ \boxed{O(n)} \]
⭐ 一句话记忆

顺序表：地址连续，可以“跳着找” → O(1)
单链表：地址不连续，只能“顺着找” → O(n)

你可以把它想成：

顺序表 = 酒店房间 🏨
知道房间号，直接坐电梯/导航过去。

单链表 = 寻宝游戏 🗺️
第一个纸条告诉你第二个在哪，第二个再告诉你第三个在哪……只能一个个找。

不过要注意：单链表并不是所有操作都是 O(n)。比如在“已经知道某个节点地址”的情况下插入一个节点，可以做到 O(1)。

### 助手

对，你这张图正好就是单链表插入操作，而且你红笔写的两句话是关键：

D->next = B->next
B->next = D

我给你把这一步彻底讲明白。

现在的链表

原来：

纯文本
head → A → B → C

现在要求：把 D 插入到 B 和 C 之间。

也就是变成：

纯文本
head → A → B → D → C
第①步：先找到 B

图里：

纯文本
head → A → B → C
           ↑
           P

P 指向 B。

因为我们要把 D 插在 B 后面。

第②步：让 D 指向 C

这就是你写的：

C
D->next = B->next;

为什么？

原来：

纯文本
B → C

所以：

纯文本
B->next

保存的就是 C 的地址。

于是：

纯文本
D->next = B->next;

就相当于：

纯文本
D → C

现在暂时变成：

纯文本
B → C
↓
D → C
第③步：让 B 指向 D

再执行：

C
B->next = D;

于是：

纯文本
B → D → C

最终：

纯文本
head → A → B → D → C
⚠️ 为什么一定要先写第一句？

这个特别重要，考试很喜欢考。

正确顺序：

C
D->next = B->next;
B->next = D;

如果你反过来：

C
B->next = D;
D->next = B->next;

第一句执行以后：

纯文本
B → D

这时候 B->next 已经不是 C 了，而是 D。

于是第二句实际上变成：

纯文本
D->next = D;

结果：

纯文本
B → D
    ↑
    └── D

C 就丢了！

所以你可以记一个非常简单的口诀：

先接后面，再断前面。

或者更准确：

先让新节点接上原来的后继，再让前一个节点指向新节点。

也就是：

\[ \boxed{D.next=B.next} \]

↓

\[ \boxed{B.next=D} \]

这就是你图中红色 ②、③ 两步。

顺便你下面写的 “查 O(n)、改 O(n)” 也正好对应一个很重要的知识点：单链表插入本身是 O(1)，但如果你还不知道 B 在哪里，先找 B 要 O(n)，所以整个“按位置插入”通常是 O(n)。
